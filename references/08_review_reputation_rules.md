# 口コミ・評判記事の追加制作ルール

ジャンル・商材・キーワードを問わず、口コミ・評判記事の構成、執筆、チェックに適用する。

工程1で口コミ調査計画を作り、工程3.5で構成、工程5で本文、工程6・7で公開前チェックと納品判定を行う。

口コミ・評判記事では、`05_article_writing.md` の一般記事向けSNS・口コミ規則より、このファイルを優先する。CTAの配置とリンクの扱いは `07_execution_contract.md` に従い、リンクを創作しない。

---

# 1. 目的と基本方針

口コミ・評判記事の目的は、

**読者が案件の魅力と選ぶ理由を理解し、前向きに申込み・購入を検討できる状態を作ること**

である。

* 肯定的な口コミを中心に構成する
* 案件の具体的なメリットと「選ぶ理由」を本文の主役にする
* 読者の申込み意欲を高めることを最優先する
* 冒頭で結論（どんな人に、なぜおすすめか）を示し、メリット → 得られる価値 → 向いている人 → 申込み前の確認事項 → 次の行動へ自然につなげる
* 口コミの羅列や、注意点を過度に増やした調査レポートにしない
* 終盤は注意点の再掲で終わらせず、読者に合う条件と次の行動を明確にする

ただし、SKILL.mdの絶対ルール（捏造禁止、根拠のない「最安」「No.1」等の禁止）は口コミ・評判記事にも適用する。

---

# 2. 構成（工程3.5）

各H2は原則として、

**読者が得る価値 → その根拠（公式情報・口コミ） → 自分に合う選び方**

の順で読める構成にする。

* 案件固有のメリット・選ぶ理由を扱うH2を記事前半に置く
* 口コミは「価値の根拠」として各H2に配置するか、口コミをまとめたH2を設ける
* 同じ注意・確認行動を複数のH2で繰り返す設計を避け、必要な注意は判断に役立つ1箇所へ集約する
* 口コミの件数を満たすために引用の羅列を本文の中心にしない

構成のみの依頼では、見出し・各節の役割がこの方針を満たすよう設計する。実際の口コミを集めずに6件を確保済みとみなさない。

---

# 3. 口コミの引用元

## 引用してよい媒体（この5つのみ）

| 媒体 | 引用時の出典 |
| --- | --- |
| 楽天トラベル | 施設のレビューページURL、投稿日 |
| みん評 | 口コミページURL、投稿日 |
| Yahoo!知恵袋 | 質問ページURL、回答日 |
| X（旧Twitter）の投稿 | 投稿URL（X埋め込みで掲載してよい） |
| YouTubeのコメント | 動画URL（取得できればコメントへのリンク）、コメント投稿者名、投稿時期 |

これらの媒体に投稿された利用者の声は、実利用者の口コミとして扱ってよい。

## 引用してはいけない媒体

* 楽天市場
* Amazon
* 価格.com
* @cosme

上記4媒体のレビューは、記事内で引用・転載・要約掲載しない。

## その他の媒体

上記の引用可能5媒体以外（個人ブログ、比較サイト、公式サイト内レビュー、Googleマップ等）からは口コミを引用しない。必要な場合は傾向把握の参考にとどめる。

---

# 4. 口コミの件数と選び方

* 引用可能5媒体から、**最低6件、理想10件**の口コミを掲載する
* 肯定的な口コミを中心に選ぶ
* 案件の具体的なメリット（価格、使いやすさ、サポート、効果の実感、手続きの簡単さ等）が伝わるものを優先する
* 異なる投稿者の口コミを使う。同一人物の複数投稿は1件として数える
* 明らかな宣伝投稿、業者・運営者による投稿、アフィリエイト目的の投稿は数えない
* 可能な範囲で複数の媒体から選ぶ
* ネガティブな口コミの直接引用は原則行わない

追加調査後も引用可能5媒体から6件を確保できない場合は、架空・出典不明の引用や引用NG媒体で補わない。何件足りないか、調査した媒体を納品メモへ記載し、未完成として扱う。

---

# 5. 口コミの調査記録

各採用口コミについて、調査メモ（納品メモに記載）へ以下を記録する。

* 媒体名
* 原文（引用する部分）
* 投稿者を区別できる情報（表示名等）
* 投稿URL（YouTubeは動画URL）
* 投稿日（不明な場合は確認日と分かるように記録）
* 対象の商品・プラン・施設等（確認できる範囲）

---

# 6. 引用の書き方

* 原文と照合した短い範囲を引用する
* 意味が変わる切り取り・改変・言い換えをしない（明らかな誤字の補正もしない）
* 各口コミに媒体名と出典リンク、投稿日（または確認日）を添える
* Xの投稿は02の「X埋め込み」を使用してよい。埋め込みも引用件数に含める
* それ以外の媒体は02の「口コミ引用ブロック」を使用する
* 口コミから性能・効果・満足率・故障率などを推定しない
* 執筆者自身の体験を創作しない
* 引用した口コミを、全利用者の評価を代表するもののように書かない（「すべての利用者が高評価」「悪い口コミはない」等を書かない）

---

# 7. ネガティブ情報の扱い

* ネガティブ情報は購入判断に重要なものだけに絞る
* ネガティブな口コミは直接引用せず、論点を短く要約する
* 同じ段落または直後に、発生条件・対象範囲、確認方法、対策、代替手段、案件の強みとの関係のうち適切なものを示し、前向きな着地点を作る
* 見出し・まとめでネガティブ情報を繰り返し強調しない
* 料金、契約条件、安全性、重大な制約など判断に不可欠な事実は隠さず、事実と異なる説明で打ち消さない
* フォローは根拠が確認できる具体策とし、「気にする必要はない」等の根拠のない安心表現を使わない

---

# 8. 本文（工程5）

* 各H2の本文も「価値 → 根拠 → 選び方」の順に書く
* 商品・サービス固有の利点と、読者が受ける価値を具体化する
* 根拠のない効能や確約を足さない。価格・条件・重要な制約は残す
* 同じ注意・確認行動を複数の節で繰り返していないか段落単位で確認する
* CTAの配置とリンクは07 #5に従う。訴求文は記事内で確認した案件の強みを使う

---

# 9. 公開前チェック（工程6）

完成候補稿を広告記事として通読し、以下を1項目ずつ確認する。満たさない項目は修正して再確認する。点数による採点は行わない。

* [ ] 冒頭と結論で、案件の魅力とおすすめできる読者が明確に伝わる
* [ ] 各H2が「価値 → 根拠 → 自分に合う選び方」の順で読め、案件固有のメリットが本文の主役になっている
* [ ] 読み終えた読者が、選ぶ理由を具体的に理解し、申込み・購入を前向きに検討できる
* [ ] 引用可能5媒体（楽天トラベル、みん評、Yahoo!知恵袋、X、YouTubeコメント）からの口コミが最低6件ある
* [ ] 楽天市場・Amazon・価格.com・@cosme、その他の媒体からの引用がない
* [ ] 肯定的な口コミが中心で、ネガティブな口コミを直接引用していない
* [ ] 各口コミに媒体名・出典リンク・投稿日（または確認日）があり、原文と一致している
* [ ] ネガティブ情報の同段落または直後に、事実に基づくフォローや具体策がある
* [ ] 判断に不可欠な重大事実（料金・契約条件・安全性等）を隠していない
* [ ] 同じ注意・確認行動を複数の節で繰り返しておらず、注意点がメリットを圧迫していない
* [ ] 価格・特典・納期・保証など変動する重要情報を、納品前に最新の公式表示と照合した
* [ ] CTAの訴求文に、確認済みの案件の強みを使っている（位置・数・リンクは07 #5、check_article.pyで確認）
* [ ] 読後の次の行動が具体的に分かる

選ぶ理由や申込み意欲が弱いと判断した場合は重大問題とする。調査情報と不可欠な事実を残したまま、見出し・導入・各H2・結論の訴求文を書き直し、再度チェックする。CTAを増やしたり、重大な事実を消したりして合格にしない。

書き直しは最大2回までとする。2回書き直しても満たせない場合は、未完成として理由と改善案を納品メモに記録する。

---

# 10. 納品メモへの記載

納品メモには以下を簡潔に記載する。

* 公開前チェックの結果（各項目の可否）
* 口コミの採用件数と媒体別の内訳
* 各口コミの調査記録（5の項目）
* 不足件数と調査した媒体（不足がある場合）
* 変動情報の確認日
* 広告表記（WordPress共通設定）の確認状態
* 申込みリンクの状態（受領リンク使用 / 公式サイトURL仮設定 / AFF_LINK仮置き）

口コミ不足などで条件を満たさない場合は、未完成と明記し、不足内容と次に必要な調査・確認事項を伝える。
