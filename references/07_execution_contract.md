# 実行環境・使用ツール・出力形式

このファイルは、SKILL.mdの工程を実行する際のツールの使い方、CTAモード、ファイル出力を定める。開始時に必ず読む。

このSkillは外部の文字数計測プラグインを使用しない。存在しないAPI・MCP接続URL・認証方式を推測して呼び出さない。

# 1. 使用するツールと役割

# 2. Google検索1ページ目の確認（クラウドブラウザ最優先）

## 使用するブラウザの順序

1. **クラウドブラウザを最優先**にする。実行環境で提供されるクラウドブラウザを選び、実際にGoogle検索結果を開く。パソコンのブラウザとは別の環境であることを、ツールの説明・接続先情報から確認する。使えるクラウドブラウザを試さずに、ローカルブラウザ、ラッコキーワード、Web検索へ進まない。
2. クラウドブラウザが提供されていない、接続できない、操作機能が対応していない等の**通常の機能・接続上の理由**で利用できない場合は、**利用者のパソコンのブラウザのシークレットウィンドウ**でGoogle実検索を行う。提供された正規のブラウザ操作機能を使い、既存の通常ウィンドウを代用しない。シークレットであることを操作結果・ウィンドウ情報等で確認する。
3. パソコンのブラウザは**可能な限りバックグラウンドで操作**し、利用者の作業中のウィンドウやタブを切り替えず、既存タブを流用しない。前面化・キーボード占有が避けられない環境では、その制約を簡潔に知らせ、バックグラウンドで実行できたふりをしない。
4. シークレットウィンドウの作成・接続・操作が未対応、またはブラウザ接続がない場合は、その理由を記録して下記の代替資料へ進む。拡張機能の設定やシークレット利用権限を勝手に変更しない。対応していないAPI・操作機能を推測して呼び出さない。

クラウドブラウザもローカルのシークレットも機能上利用できない場合、既存のラッコキーワード資料やWeb検索で可能な調査を続ける。Google実SERPを確認したとは報告しない。

## Google側の認証・アクセス制限

GoogleがCAPTCHA、bot確認、不審なトラフィック等の制限を表示した場合は、通常のツール故障と区別する。上位のブラウザ利用ルールに従い、許可される一度の低負荷な再読み込み等を除き反復しない。**制限の回避を目的に、別ブラウザ・別セッション・シークレット・別ネットワークへ切り替えない。** 必要な認証は環境の正規手順に従う。解除できない場合は制限と未確認範囲を記録し、許可された代替資料で進める。

## 検索条件と記録

* 日本語・日本向けの検索を使う。URL例：`https://www.google.co.jp/search?q=（キーワード）&hl=ja&gl=jp`。この指定だけでIP所在地や完全な非個人化を保証したとは扱わない。
* 1ページ目の通常オーガニック結果を上から順に、順位・タイトル・URL・サイト種別（公式／法人SEO／個人ブログ／アフィリエイト／EC／ポータル／ニュース／Q&A／動画）で記録する。広告・AI概要を通常順位に含めない。
* 広告、AIによる概要、強調スニペット、PAA（他の人はこちらも質問）、関連検索、動画・画像枠の有無と内容を別記する。
* リサーチDBへ、確認日時・検索クエリ・取得元（クラウド／ローカルのシークレット／代替資料）・言語／地域設定・確認できたログイン状態とシークレット状態・背景操作の可否・切替理由・確認範囲を残す。確認できない状態は「未確認」とする。

## ブラウザ実検索ができない場合の代替資料

1. ラッコキーワードの見出し抽出が返す `position`（Google検索順位）とURLを代替資料として使う。
2. PAA・関連検索はラッコキーワードのその他キーワード・関連キーワードで補う。
3. それも使えない場合はWeb検索ツールの結果を使う。

いずれも「Google実SERP未確認」とし、資料の取得元・確認範囲・ブラウザを利用できなかった理由を明記する。実際のGoogle検索結果を直接確認していない順位・PAAを「Google確認済み」と書かない。

# 3. ラッコキーワードの使い方

## 連携の確認

工程1でラッコキーワードが必要になった時点で、ラッコキーワードのツール（見出し抽出など）が使えるか確認する。Skill開始時に一括確認しない。

## 見出し抽出（headline）

* `keyword`：対象キーワード
* `limit`：20
* 返却される各ページの `position`（順位）、`url`、`title`、`headlines`（h1〜h4）、`wordCount`（文字数）と、`summary` の平均・最小・最大文字数を記録する
* `summary.averageWordCount` は上位20ページ全体の平均であり、記事の目標文字数には使わない。目標文字数は、選定したSEO競合5本の `wordCount` から `scripts/calc_targets.py` で算出する

## 未連携の場合

ラッコキーワードが連携されていない場合は、以下の順で進める。

1. ブラウザ／Web検索でできるSERP確認、SEO競合選定、競合本文分析、検索意図分析、一次情報調査を先に実行する
2. 競合文字数が必要になった時点で、ユーザーへ以下を依頼して停止する

依頼文の例：

```text
ラッコキーワードとの連携が確認できなかったため、競合記事の文字数を取得できませんでした。
お手数ですが、ラッコキーワードの「見出し抽出」で「（キーワード）」を調べた結果を添付してください。
（CSVダウンロード、または画面のURL・タイトル・文字数が分かる部分のコピー／スクリーンショットで構いません）
添付をいただいたら、続きの工程から再開します。
```

3. 添付を受け取ったら、資料内のURL・文字数を使って `calc_targets.py` を実行し、工程1の続きから再開する

AIが競合本文の文字数を推測・概算・手計算して代用しない。

# 4. 同梱スクリプト

## Pythonの事前確認・未導入時の対応

全文制作では、長時間の調査に入る前に以下を実施する。「構成だけ」の依頼はスクリプトが必要になった時点で確認する。

1. **AIがコードを実行する環境**で `python3 --version` を確認する。なければ `python --version` を試し、Python 3.10以上か確認する。ChatGPT側のPython実行機能がある場合はそこで確認する。必要なのはスクリプトを動かす環境であり、生徒のパソコンへのインストールではない。
2. 未導入・旧版の場合、利用環境に提供されている正規のパッケージ管理・環境構築機能でPython 3.10以上を導入する。導入方法はその環境の手順に従い、公式配布元・OSの標準パッケージ管理を使う。権限昇格・端末設定変更が必要な場合は、環境の承認手順に従う。外部の不明なインストーラーや権限回避を使わない。
3. 導入後はバージョンを再確認し、本体ディレクトリを基準に `python3 scripts/calc_targets.py --help` と `python3 scripts/check_article.py --help` を実行する。`python` を選んだ環境ではそのコマンド名を使う。単にファイルを取得しただけで利用可能と判断しない。
4. 同梱スクリプトはPython標準ライブラリと同梱モジュールのみを使う。通常、追加のpipパッケージや個人APIキーは不要。GitHubローダー利用時は取得済みの本体側のscriptsを使う。
5. 導入できない、コード実行機能自体がない、または実行に必要な承認がない場合は、その制約と必要な対応を簡潔に知らせる。Pythonのない環境での実行やチェックを行ったふりをしない。独立してできる調査・構成は進めてよいが、目標文字数の算出や最終チェックは未実行として残し、完成とは報告しない。
6. 生徒のパソコンでスクリプトを実行する運用を選んだ場合に限り、そのパソコンのPython導入が必要になる。AI側の実行環境で処理できる場合、生徒へローカル導入を求めない。

スクリプトはこのSkillの `scripts/` にある。確認したPythonで実行し、返却されたJSONをそのまま記録する。AIは返却値を再計算・補正しない。実行エラー時の扱いは06 #14。

## calc_targets.py（目標文字数・工程1）

```bash
python3 scripts/calc_targets.py --json '[{"url":"https://example.com/a","count":8200},{"url":"https://example.com/b","count":null}]'
```

* `count` が取得できなかったURLは `null` で渡す（failedとして平均から除外される）
* 返却値：results、success_count、failed_count、reliability、average_count、target_110、target_min、target_max
* 算出式：target_110＝平均×1.1、target_min＝平均×0.8、target_max＝平均×1.2（四捨五入）

## check_article.py（完成記事の一括チェック・工程6）

```bash
python3 scripts/check_article.py {スラッグ}.md --target-min （記事制作target_min） --target-max （競合由来target_max）
python3 scripts/check_article.py {スラッグ}.md --target-min … --target-max … --no-case   # 案件なしの記事
```

1回の実行で以下をまとめて確認する。

* **文字数**：CTA（`▼CTA`〜`▲CTA`の範囲と`cta-box`）、埋め込み、HTMLコメント、タグ、空白を除いて数える。character_count、achievement_rate、status（under_target / within_target / over_target）を返す
* **構造**：冒頭の並び、「この記事を読んでわかること」が見出しでなく5項目か、情報最終確認日が導入文末尾に1件か、メインCTAの位置と数、具体例CTAと同じ見出し内に表があり、表とCTAの間に該当ページへのリンクがあるか、CTA範囲外の広告リンク、見出しブロックの形式、CTAリンクの属性、最後のH2がまとめで8〜15項目か、H3が1つだけのH2、吹き出しの数、表の1列目、空タグ・旧形式クラス、本文のPR表記、Gutenbergブロックの対応
* **具体性**：丸投げ・省略・ぼかし表現を、前後の文脈つきで一覧にする（基準は09）

返却値の見方：

* `errors`：修正必須。0件になるまで修正して再実行する
* `warnings`：1件ずつ見直す。残す場合は理由を納品メモに記録する（リンクのない「丸投げ」とPR表記はerrorとして扱われ、残せない）
* `specificity_hits`：具体性の検出箇所。09 #5に従って書き換える

個別に使う場合は `count_draft.py`（文字数のみ）、`check_specificity.py`（具体性のみ）も実行できる。

CTAを正しく除外して計測するため、02の `cta-box` とCTAの開始・終了コメントを必ず維持する。本文をCTA枠に入れて除外したり、計測用に短縮したHTMLを計測したりしない。

# 5. CTAの配置とリンク（CTAのルールはこの節が正）

## 配置

CTAは次の2種類だけを設置する。

* **メインCTA**：「この記事を読んでわかること」の後、**最初のH2の直上に1箇所**（HTMLは02 #15）
* **具体例CTA**：人によって結果が変わる指定案件の情報（見積もり・査定額・料金シミュレーション等）を3パターンの具体例で示した直後（09 #2、HTMLは02 #15-1）。該当する箇所の数だけ置いてよい

上記以外の位置にCTAを置かない。訴求文には、リサーチDBで確認済みの案件の強み・条件だけを使う。

## リンク

どちらのCTAも、リンクは以下のモードに従う。具体例CTAは、可能なら見積もり・査定・シミュレーションの該当ページURLを使う。

### 案件あり・申込みリンクあり

* ユーザーから受け取った実URLだけを使用し、推測・改変・短縮や他サイト用リンクの流用をしない
* 実URLを `AFF_LINK` へ戻さない

### 案件あり・リンク未受領

* CTAのリンクに、その案件の**公式サイトURL**を設定する
* 公式サイトURLは、検索結果やブラウザで実際に開いて案件の公式サイトであることを確認したものだけを使う（トップページ、または申込み・サービス紹介の公式ページ）。URLを推測して作らない
* CTAの開始コメントを `<!-- ▼CTA 公式サイトURLを仮設定中。アフィリエイトリンク取得後に差し替えてください -->` とする
* 納品メモの公開前作業に「CTAの公式サイトURLをアフィリエイトリンクへ差し替える」を明記する
* 公式サイトURLを確認できない場合のみ、`AFF_LINK` を仮置きし、公開前作業に差し替えを明記する
* リンク待ちで記事制作を止めない

### 案件なし

* CTA・AFF_LINKを作らない
* 冒頭は「導入文 → この記事を読んでわかること → 最初のH2」。`check_article.py` は `--no-case` で実行する
* サービスを取り上げる場合は、検索意図に適する選択肢として扱い、公式URLは実際に確認したものだけを使う
* CTA関連のチェック項目は「対象外（案件なし）」と記録する

* ファイルの中身をそのままWordPressのコードエディタへ貼り付けられる状態にする

## 納品メモファイル：`{スラッグ}_納品メモ.md`

* 06 #20の内容をMarkdownで記載する。記事本文HTMLは含めない

## チャットでの報告

* 記事本文HTMLをチャットへ貼り付けない
* 以下だけを簡潔に示す
  * 使用スキル名とバージョン（SKILL.mdの「バージョン」の値）
  * 推奨タイトル
  * 文字数の計測結果（character_count / target_min / status）
  * 完成判定（完成 / 未完成と理由）
  * 重要な公開前作業
  * ダウンロードリンク：記事本文ファイル、納品メモファイル（参考として `{KW}_リサーチDB.md` も添える）

# 7. 完了報告の区別

形式チェック、スクリプトの動作確認、実記事の品質確認は別々に報告する。小さな動作テストだけで実記事が完成したとは報告しない。
