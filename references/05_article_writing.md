本文作成前に、作業ファイル `{KW}_リサーチDB.md` と `{KW}_構成.md` を読み直す（07 #6）。HTMLは02に従う。

# 1. 本文執筆の目的

本文では、

**検索ユーザーが知りたい答えを早く示し、根拠・条件・比較・例外を理解したうえで、自分に適した判断と行動を完了できる状態**

を作る。

指定案件がある場合は、

**検索意図への回答の延長として、読者にとって合理的な選択肢として提案する。**

# 2.5 独自切り口の本文実装

工程1で「採用する独自切り口」とした回答改善・異なる角度の内容と、「採用する提供価値」を、工程3の対応表に沿って本文で実際に回答する。

独自切り口を、

「競合に書いていない情報の紹介」だけで終わらせない。

読者が、

何を判断できるようになるか
どの条件で結論が変わるか
何を避けられるか
どの選択肢が適するか

まで理解できるように、

一次情報
数値
条件
比較
計算
対象外・例外
判断分岐

等を用いて具体化する。

独自切り口の重要度が高い場合は、記事末尾ではなく読者が判断する位置で提示する。

競合記事に存在しないという理由だけで掲載しない。

判断基準は、

「この情報があることで、SERP上位記事だけを読んだ場合より読者の意思決定が改善するか」

とする。

* 「詳しく比較する」「条件別に解説する」という予告で終えず、実際の比較結果・適用条件・結論が変わる境界まで示す。
* 比較は対象・時点・期間・用途など必要な条件をそろえる。計算は確認済みの入力値・前提・計算式を示し、条件をそろえられない点や未確認値も明記する。
* 読者別の切り口は、主たる検索意図への回答を維持して実装する。A・Bの両方を無理に本文へ追加しない。
* 競合の不足分析・「多様性枠」などの制作上の説明は作業ファイルに残し、記事本文では読者に必要な答えと判断材料を提示する。
* 根拠不足で予定した価値を実現できなければ、追加調査するか採用方針・構成を修正し、リサーチDBと構成ファイルも更新する。計画にあるだけで実装済みとしない。
* 体験談・調査・写真・動画は採用理由に沿って必要な場合に使い、提供されていない体験を作らない。

導入文では必要な範囲で、

# 7. 冒頭の配置

記事冒頭は以下の順とする。

1. 導入文（末尾に情報最終確認日）
2. 「この記事を読んでわかること」（見出しにしない。具体的な結論5項目）
3. メインCTA（案件がある場合のみ。07 #5）
4. 最初のH2

冒頭の並びはこの節が正とする。具体的なHTMLは02に従う。

# 7-1. 情報最終確認日

記事の情報鮮度を示す日付は、

**記事作成日ではなく「情報最終確認日」**

として扱う。

情報最終確認日は、導入文の最後に通常段落として原則1回だけ記載する。

表記例：

`※記事内の変動しやすい情報は、YYYY年M月D日時点で確認しています。`

この段落は導入文の一部として扱うため、冒頭配置は、

**導入文（末尾に情報最終確認日）→「この記事を読んでわかること」→ CTA →最初のH2**

とする。

記事更新時は、重要な変動情報を再確認した日へ情報最終確認日を更新する。

情報を再確認せず、日付だけを新しい日付へ変更してはいけない。

# 7-2. 本文中の日付

記事の鮮度を示す目的だけで、

* YYYY年M月D日現在
* YYYY年M月時点
* 記事執筆時点では
* 記事作成時点では

などを本文・表・吹き出し・CTA・まとめへ繰り返し記載しない。

記事全体の情報確認時点は、冒頭の「情報最終確認日」で一元管理する。

ただし、以下のように日付そのものが読者の判断材料になる場合は、本文中にも具体的な日付を残す。

* キャンペーン開始日・終了日
* 申込期限
* クーポン有効期限
* 発売日
* 価格改定日
* サービス開始・終了日
* 制度改定日・適用開始日
* 調査・統計の対象期間
* その他、日付を省略すると判断を誤る情報

これらは記事作成日ではなく、その事実固有の日付として扱う。

# 29. SNS・口コミ

口コミ・評判記事では `08_review_reputation_rules.md` を優先し、引用可能5媒体（楽天トラベル、みん評、Yahoo!知恵袋、X、YouTubeコメント）から最低6件の口コミを掲載する。

それ以外の記事では、以下に従う。

* 検索意図や購入・申込判断に必要な場合のみ口コミ・SNSを使用する
* 全記事へ口コミセクションを設けない
* 投稿数を固定ノルマにしない。不要なら0件でもよい
* 引用する場合も、引用元は08と同じ5媒体に限定する
* 楽天市場、Amazon、価格.com、@cosmeのレビューは引用・転載・要約掲載しない
* Xは実在投稿だけを使用し、URLを推測しない（Threadsは引用元に含まれないため使用しない）

# 43. 最終原則

本文では常に、

**「この情報によって、検索ユーザーは何を理解し、何を判断できるようになるか」**

を基準にする。

理想の流れは、

**検索意図へ回答
→ 根拠・条件・比較を示す
→ 読者が自分に合う選択肢を判断する
→ 指定案件が条件に合えば合理的な候補として提案する
→ 読者が納得して行動を選ぶ**

ことである。

案件CVは、

**検索ユーザーへ十分な判断材料を提供した結果として生まれる状態**

を目指す。
